Driving the agent from your own code

The playground is one client of this API, not a privileged one. Five calls start a conversation on a named graph, keep it alive, and stop it — everything the browser does, and nothing it can do that curl cannot.

read from ai_agents/server/internal  ·  2026-09-17  ·  port from SERVER_PORT, 8081 on the board

Before anything else

Every response has the same three fields, and the HTTP status is not one of them. 

{ "code": "0", "msg": "success", "data": null }
code is a string, and "0" is the only success. A call that failed still returns HTTP 200 in most paths, so branching on the status code will tell you everything worked when it did not.

Port 8081 rather than the default 8080: on this board the vendor's LLM daemon holds 8080, and SERVER_PORT in ai_agents/.env moves this server out of its way. Elsewhere it is 8080.

A whole conversation

Paste this. It picks a channel, gets a token, starts the board's local-speech graph, holds it open for a minute and stops it. 

#!/usr/bin/env bash
API=http://127.0.0.1:8081
CH=demo-$RANDOM
GRAPH=voice_assistant_sherpa_full

TOKEN=$(curl -s -X POST $API/token/generate \
  -H 'Content-Type: application/json' \
  -d "{\"request_id\":\"1\",\"channel_name\":\"$CH\",\"uid\":12345}" \
  | python3 -c 'import json,sys; print(json.load(sys.stdin)["data"]["token"])')

curl -s -X POST $API/start \
  -H 'Content-Type: application/json' \
  -d "{\"request_id\":\"2\",
       \"channel_name\":\"$CH\",
       \"graph_name\":\"$GRAPH\",
       \"user_uid\":12345,
       \"bot_uid\":54321,
       \"token\":\"$TOKEN\",
       \"timeout\":60}"

# the worker is reaped if nothing pings it before its timeout
for i in $(seq 6); do
  sleep 10
  curl -s -X POST $API/ping -H 'Content-Type: application/json' \
    -d "{\"request_id\":\"3\",\"channel_name\":\"$CH\"}"
done

curl -s -X POST $API/stop -H 'Content-Type: application/json' \
  -d "{\"request_id\":\"4\",\"channel_name\":\"$CH\"}"

The audio itself never touches this API. It goes over Agora RTC, on the channel and uids named here — which is what the token is for.

The five calls

01

Find out which graphs exist

Read from the tenapp's property.json at request time, so a graph added to that file needs the server restarted before it appears here. 

curl -s http://127.0.0.1:8081/graphs | python3 -m json.tool
{ "code": "0", "msg": "success", "data": [
    { "name": "voice_assistant_sherpa_full", "auto_start": false },
    { "name": "voice_assistant_sherpa_tts",  "auto_start": false },
    { "name": "voice_assistant_soniox_ambarella_llm", "auto_start": false },
    ... ten more
] }
02

Get a token for the channel

One channel, one uid. The uid here is the human's, the one your client will join RTC with. 

curl -s -X POST http://127.0.0.1:8081/token/generate \
  -H 'Content-Type: application/json' \
  -d '{"request_id":"1","channel_name":"demo","uid":12345}'
{ "code": "0", "msg": "success", "data": {
    "appId": "a1b2…", "token": "a1b2…",
    "channel_name": "demo", "uid": 12345
} }

With AGORA_APP_CERTIFICATE empty, token comes back as the app id itself. That is correct for an app-id-only Agora project, not a failure.

03

Start a worker on that channel

graph_name is where you choose the agent. The channel name is the worker's identity for the rest of its life — starting twice on one channel returns 10003 rather than a second worker. 

curl -s -X POST http://127.0.0.1:8081/start \
  -H 'Content-Type: application/json' \
  -d '{
        "request_id": "2",
        "channel_name": "demo",
        "graph_name": "voice_assistant_sherpa_full",
        "user_uid": 12345,
        "bot_uid": 54321,
        "token": "<from step 02>",
        "timeout": 60
      }'
FieldTypeNotes
channel_name requiredstring The worker's identity. Blank gives 10004, a duplicate gives 10003.
graph_namestring A name from /graphs. Not validated here — a name that does not exist fails when the worker starts, as 10101.
user_uiduint32The human's RTC uid.
bot_uiduint32The agent's RTC uid.
tokenstringFrom /token/generate.
timeoutint Seconds without a ping before the worker is stopped. Falls back to WORKER_QUIT_TIMEOUT_SECONDS.
propertiesobjectPer-node overrides — below.
request_idstringYours. Echoed into the server log.
tenapp_dirstring Ignored. The server always uses the directory it was launched with, deliberately.
04

Keep it alive

Every ping stamps the worker. One whose last stamp is older than its timeout is stopped by the server, so a client that disappears leaves no process behind. 10002 means it is already gone. 

curl -s -X POST http://127.0.0.1:8081/ping \
  -H 'Content-Type: application/json' \
  -d '{"request_id":"3","channel_name":"demo"}'
05

Stop it

curl -s -X POST http://127.0.0.1:8081/stop \
  -H 'Content-Type: application/json' \
  -d '{"request_id":"4","channel_name":"demo"}'

curl -s http://127.0.0.1:8081/list shows what is running now, which is the quickest way to find a worker someone forgot to stop.

What /start writes into the graph

The graph in property.json is a template. Four fields of the request are injected before the worker starts, so a new extension picks them up by declaring the property — no server change.

Request fieldExtensionProperty it lands in
channel_nameagora_rtc, agora_rtmchannel
user_uidagora_rtcremote_stream_id
bot_uidagora_rtcstream_id
bot_uidagora_rtmuser_id — as a string
tokenagora_rtc, agora_rtmtoken

Changing a setting for one session

properties merges into the graph for this worker only. Nothing on disk is touched, and the next session starts from the file again. 

curl -s -X POST http://127.0.0.1:8081/start \
  -H 'Content-Type: application/json' \
  -d '{
        "request_id": "2",
        "channel_name": "demo",
        "graph_name": "voice_assistant_sherpa_full",
        "properties": {
          "stt": { "rule2_min_trailing_silence": 0.8 },
          "tts": { "speed": 1.1 },
          "llm": { "prompt": "用中文简短口语回答。" }
        }
      }'

The keys are node names from the graph, not addon names. In voice_assistant_sherpa_full they are agora_rtc, stt, llm, tts, main_control, message_collector, weatherapi_tool_python and streamid_adapter.

A property whose value is an object — params, typically — is merged key by key, so naming one leaves the rest alone. A property whose value is a scalar is replaced outright.

This is how to try a setting without editing a file. A different endpoint rule, a faster voice, another system prompt: start a session with it, listen, stop. No restart, nothing to undo.

When it goes wrong

ECONNREFUSED on 8081silent

Either server/bin/api was never built — it is git-ignored, so a fresh clone has none — or AGORA_APP_ID is not exactly 32 characters and the server called os.Exit(1) at startup. The reason is in /tmp/task_run.log, not in the response, because there is no response.

Parse Error: Invalid header tokensilent

You reached the board's LLM daemon on 8080 instead of this server. Its 404 page has a header line with no colon, which no HTTP client will accept. Check SERVER_PORT.

HTTP 200 with a non-zero codesilent

The call failed. Read code; the status said nothing about it.

A new graph does not appear in /graphs

The list is read from property.json per request, but the playground caches it — and adding a graph is not hot-reloadable anyway. Restart the server and the frontend. Editing values inside an existing graph does take effect on the next session.

The agent joins but never answers

On this board the LLM serves --max_user 1 and holds a session for 180 seconds after each reply. A second worker started while the first is still up will be refused down there, with nothing wrong at this level.
