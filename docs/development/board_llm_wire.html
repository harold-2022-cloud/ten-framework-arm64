The board's LLM speaks HTTP, but only just

Ambarella's llm_demo serves one endpoint on an N1-655. Four headers, a plain-text body, and a response that streams one character per event. What follows was read off the wire, not out of a header file.

measured 2026-09-14 → 2026-09-17  ·  n1-655_deepseek_r1_distill_qwen_7B_1NVP  ·  launcher: run_llm_demo.sh --model_type 9 --max_user 1

Request

The body is the prompt itself — UTF-8 text, no JSON envelope, no role markers. The board keeps the conversation history on its side, keyed by Session-Id, so only the newest turn is sent.

HeaderValueWhat it does
Session-Id required 815217 A non-zero decimal integer. Parsed numerically, so a hex id either leads with a letter and parses to zero, or leads with a digit and is truncated at the first letter. Both fail silently in their own way.
Model-Type 9 Matches the --model_type the daemon was started with.
Stream-Off 0 0 streams the reply as it generates. 1 returns the whole thing at once — still labelled text/event-stream, but with no data: framing in the body.
Reset-En 1 1 clears the board-side history for this session before answering. 0 keeps it, and the board re-processes the whole history each turn.
Content-Type text/plain; charset=utf-8 The body is the prompt. Not required by the daemon, but it is what the guide sends and what any proxy in the path will want.
Nothing here touches generation. There is no header for a length limit, a stop condition, a temperature, or the reasoning phase. Four headers is the whole surface.

curl

A first turn, streaming, with the history cleared. -N matters: without it curl buffers and the stream arrives as one block. 

# streaming, fresh conversation
curl -N -X POST http://127.0.0.1:8080/ \
  -H 'Session-Id: 815217' \
  -H 'Model-Type: 9' \
  -H 'Stream-Off: 0' \
  -H 'Reset-En: 1' \
  -H 'Content-Type: text/plain; charset=utf-8' \
  --data '讲一个笑话。'

The turn after it

Same Session-Id, Reset-En: 0. The board still has the previous exchange and will read it again before answering.

curl -N -X POST http://127.0.0.1:8080/ \
  -H 'Session-Id: 815217' \
  -H 'Model-Type: 9' \
  -H 'Stream-Off: 0' \
  -H 'Reset-En: 0' \
  --data '再讲一个。'

When curl gives up

The board's error pages are not well-formed HTTP, and curl will not hand over a response it refuses to parse — it reports (8) Header without colon and stops. Speak the protocol yourself to see the bytes. 

python3 - <<'PY'
import socket
body = "讲一个笑话。".encode()
req = (b"POST / HTTP/1.1\r\n"
       b"Host: 127.0.0.1:8080\r\n"
       b"Session-Id: 815217\r\nModel-Type: 9\r\n"
       b"Stream-Off: 0\r\nReset-En: 1\r\n"
       + f"Content-Length: {len(body)}\r\n".encode()
       + b"Connection: close\r\n\r\n" + body)
c = socket.create_connection(("127.0.0.1", 8080), timeout=180)
c.sendall(req)
raw = b""
while (chunk := c.recv(8192)):
    raw += chunk
print(raw[:400])
PY

Response

With Stream-Off: 0 the body is Server-Sent Events, one character per event. Whitespace is escaped, because a trailing space cannot survive SSE's field parsing. 

data: 在
data: 一
data: 个
data: <SP>
data: 小
data: 村
...
data: <DONE>
<SP>
one space
<NL>
one newline
<DONE>
end of stream. [DONE] also appears; accept both.
</think>
end of the reasoning phase. Everything before it is the model thinking; everything after is the answer.
There is no opening </think>'s partner. The template in prompt_config.json ends the assistant marker with an unclosed <think>, so the opening tag is in the prompt and only the closing one is generated. A parser written for this model family will look for both and find one.

Because each event carries a single character, every one of these tokens can be split across events, and a token split across two TCP chunks is the same problem one level down. Decode the byte stream incrementally and hold back anything that might still become a token — at most len("</think>") - 1 characters of lag.

One conversation at a time

The daemon runs with --max_user 1, and a session stays occupied for 180 seconds after the reply completes. 

/tmp/log.txt
[INFO] 10:26:59  From user: fd: 10, ip: 127.0.0.1, net_type: 9, content: 讲一个笑话。
[ERR]  current user num (2) > max_user_num (1), please wait 180s to see if
       there are any timeout session.
[ERR]  handle_request_from_post fail
[INFO] 10:29:00  Dev session free: Dev VA: 0xaaaab8fa01b8, fd_dev: 7, sid: 2

A client that sends each request under a fresh Session-Id therefore gets one request every three minutes. Reuse one id and separate the turns with Reset-En: 1 instead.

When it goes wrong

Three of these fail without an HTTP error to catch. The stripe marks those.

Connection closes, no response at allsilent

Session-Id did not parse as a non-zero integer. The daemon logs session_id=0 should not be 0 and hangs up; curl reports (52) Empty reply from server.

Parse Error: Invalid header tokensilent

Something else is on 8080 — or rather, you have reached the LLM when you meant to reach something else. Its 404 page's second header line is the bare word LLM, with no colon, which no HTTP parser will accept.

A reply that is all reasoning and no answersilent

The stream ended without ever sending </think>. Anything holding text back until the tag arrives will hold all of it, and a client that renders reasoning separately shows the user nothing worth reading.

current user num (2) > max_user_num (1)

Another session is still held. Wait for the 180-second timeout, or reuse the session id you already have.

Nothing on 8080 for the first 80 seconds after boot

The model is loading. It is ready when /tmp/log.txt contains a Device ENABLE line.

Generation

8–11 tokens per second is what Ambarella expects from this model on an N1-655, and 8.4–11.9 characters per second is what was measured. The rate does not depend on whether the characters are reasoning or answer.

Which makes the reasoning the whole of the wait: 44 to 523 characters of it before the first character of an answer, depending on the question. Closing the think block in prompt_config.json removes it — Ambarella's own instruction — and the first answer character then arrives in 0.2 s instead of 17.
