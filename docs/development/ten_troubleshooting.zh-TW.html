1. 第一步：日誌在哪

找錯地方是最常浪費時間的一步。一共三個位置，取決於 LOG_STDOUT：

位置內容條件
/tmp/task_run.log Next.js、tman designer、Go API server 的 stdout。
LOG_STDOUT=true 時 worker 的輸出也在這裡		 自己 tee 出來的
$LOG_PATH/app-<channel>-<ts>.log 每個 worker 一個檔 LOG_PATH 預設 /tmp/ten_agent
$LOG_PATH/property-<channel>-<ts>.json 該 session 實際使用的 graph 設定 同上
LOG_STDOUT=true 時 /tmp/ten_agent/app-*.log 可能是空的或不存在， 而 worker 明明在跑。先確認： 
grep -E '^LOG_PATH|^LOG_STDOUT' ~/ten-framework/ai_agents/.env

後面所有指令都用這個開頭，它會自動選對檔案：

L=$(ls -t /tmp/ten_agent/app-*.log 2>/dev/null | head -1); L=${L:-/tmp/task_run.log}
測試的 log 不在上面任何一處。兩種 test harness 的 conftest.py 都設成 console/stdout、level debug，沒有 file emitter。要留檔就 | tee。

3. A · 服務起不來

症狀：port 沒在聽，或 curl localhost:8080/health 沒反應

ss -tlnp | grep -E '3000|8080|49483'

A-1　背景執行被 SIGTTOU 停住

ps -o pid,stat,cmd -p $(pgrep -f 'task run|bin/api|tman designer' | tr '\n' ',' | sed 's/,$//')

STAT 出現 T 就是停住了。nohup 只擋 SIGHUP， 擋不了服務做終端控制時收到的 SIGTTOU。

停住的進程仍然持有 listening socket，所以 ss 看起來一切正常， 但它不會 accept 任何連線。只看 port 是查不出來的。

修法是給它一個真的終端：

kill -9 <那些 pid>
sudo dnf -y install tmux
tmux new -d -s ten 'cd ~/ten-framework/ai_agents/agents/examples/websocket-example && task run 2>&1 | tee /tmp/task_run.log'

看即時輸出用 tmux attach -t ten，離開按 Ctrl+B 再按 D （不要按 Ctrl+C，那會殺掉服務）。

A-2　port 3000 被別的東西佔了

ss -tlnp | grep ':3000'
docker ps --format '{{.Names}}\t{{.Ports}}' | grep 3000

實際案例：開發機的 WSL 裡有個舊的 ten_agent_playground 容器佔著 3000， 而 WSL2 的 localhost 轉發讓 Windows 的 localhost:3000 打到那裡去， 於是瀏覽器開出來是「另一個 TEN playground」。

A-3　Next.js 還在編譯

首次啟動要一到兩分鐘。task_run.log 出現 Ready on http://localhost:3000 才算好。

4. B · worker 起不來

症狀：curl -s localhost:8080/list 回 "data":[]

worker 由 Go server 在 POST /start 時 spawn。它死得夠早的話連自己的 log 檔都不會產生， 那時唯一看得到原因的是 /tmp/task_run.log：

grep -E 'handlerStart|Worker (start|stop|process)|placeholder' /tmp/task_run.log | tail -12

B-1　${env:} 變數不存在 → 進程直接自殺

E ten:runtime ten_placeholder_resolve@placeholder.c:195
  Environment variable SONIOX_ASR_API_KEY is not found, neither default value is provided.
ERROR Worker process failed err="exit status 1"

這是 core/src/ten_utils/lib/sys/general/placeholder.c 的設計行為：

變數狀態getenv結果
不存在，且 placeholder 沒有 | 預設值NULLexit(EXIT_FAILURE)，worker 立刻死
存在但是空字串""解析成空字串，worker 正常跑，稍後由 extension 自己報錯
有值值正常
最常見的原因是：.env 填了，但 task run 是在填之前啟動的。 .env 只在 task 啟動時讀一次，之後 spawn 的 worker 都繼承那個舊環境。

一條指令就能確認：

stat -c '%y' ~/ten-framework/ai_agents/.env
ps -o lstart= -p $(pgrep -f 'bin/api' | head -1)

.env 比進程新 → 一定要重啟，其他都別試。

B-2　key 存在但是空的

worker 會正常起來，錯誤要到 extension 層才出現。用驗證腳本一次看完：

./ai_agents/agents/scripts/verify_arm64_install.sh 2>&1 | grep 'used by:'
Go server 不會警告這件事。 ai_agents/server/internal/http_server.go 確實會檢查 ${env:...}， 但那段迴圈只讀節點 property 的頂層而且只處理字串。 各家 vendor 的 key 都埋在 property.params 裡，params 是物件，直接被跳過。

5. C · WebSocket 連不上

症狀：瀏覽器 ws.onerror，websocket.ts:77

那個 handler 拿不到任何細節（瀏覽器的 WebSocket error 事件不帶原因），所以只能從伺服器端查。

先理解機制

瀏覽器  ws://localhost:3000/ws/{port}      port 由前端隨機產生（8000-9000），存 localStorage
   ↓    frontend/server.js 代理
        ws://127.0.0.1:{port}
   ↓    Go server 把該 port 注入 graph（properties.websocket_server.port）
        websocket_server extension 綁上它

連線動作發生在 WebSocketClient.tsx：autoConnect: false， 只有 handleStartAgent 成功後延遲 2 秒才連，失敗則每 3 秒無限重試。

三條指令

grep 'WebSocket upgrade' /tmp/task_run.log | tail -2          # 瀏覽器要哪個 port
grep 'WebSocket proxy error' /tmp/task_run.log | tail -2      # 代理連不上
L=$(ls -t /tmp/ten_agent/app-*.log 2>/dev/null | head -1); L=${L:-/tmp/task_run.log}
grep -o "\[websocket_server\] Loaded config: {[^}]*}" "$L"    # extension 綁哪個 port
現象原因
第三條沒有輸出worker 沒起來 → 回 B
第一、三條的 port 不同port 注入失效
port 相同、只有 ECONNREFUSED 一兩筆然後就好了正常。瀏覽器比 extension 早幾百毫秒敲門，重試會接上
port 相同但一直 ECONNREFUSEDworker 中途死了，看 B

確認真的連上：

grep 'Client connected' "$L" | tail -2
# [websocket_server] Client connected: 127.0.0.1:46830

6. D · 麥克風拿不到

症狀：Cannot read properties of undefined (reading 'getUserMedia')

audioUtils.ts:178 呼叫 navigator.mediaDevices.getUserMedia()， 而 navigator.mediaDevices 是 undefined。

這不是權限被拒，是整個 API 不存在。瀏覽器只在 secure context 下提供它： HTTPS，或 localhost。用 IP 開一律沒有。

在 Console 確認：

[location.href, window.isSecureContext, !!navigator.mediaDevices]

修法是 SSH 通道 —— 在開瀏覽器的那台機器上跑：

ssh -L 3000:localhost:3000 <user>@<跑 TEN 的機器>

然後開 http://localhost:3000，不是 IP。若本機 3000 已被佔用， 換一個 port 即可（-L 3100:localhost:3000），localhost 的任何 port 都算 secure context。

另一個做法：直接在跑 TEN 的機器上開瀏覽器。

7. E · ASR 沒有結果

在哪看

L=$(ls -t /tmp/ten_agent/app-*.log 2>/dev/null | head -1); L=${L:-/tmp/task_run.log}
grep -E '\[stt\]|asr_result|asr_error|connection_status_changed' "$L" | tail -25

graph 裡 ASR 節點的 name 是 stt，所有它的 log 都以 [stt] 開頭。 換 vendor 不會改變這個前綴，因為它是節點名不是 addon 名。

要找的四行

log意義
[stt] config: {...'params': {...}}extension 實際收到的設定。先看這行，'api_key': '' 就是 key 沒進去
connection_status_changed ... 'current': 'connecting'開始連 vendor
connection_status_changed ... 'current': 'connected'連上了
send asr_error: {"code": -1000, "message": "..."}vendor 或設定的錯，message 就是原因

E-1　key 是空字串

[stt] config: {... 'params': {'key': '', 'api_key': '', 'model': 'nova-3', ...}}
send asr_error: {"code": -1000, "message": "Deepgram API key is required but missing or empty"}
connection_status_changed ... 'current': 'disconnected', 'code': -1000

回 B-1 檢查 .env 與服務的先後順序。

E-2　有連上但沒有辨識結果

grep '_send_asr_metrics' "$L" | tail -3
# metrics={'actual_send': 0, 'actual_send_delta': 0}

actual_send: 0 代表一個 byte 的音訊都沒送出去。 往上游查：麥克風（D）或 WebSocket（C）。

E-3　錯誤在 UI 上看不到

W ten:runtime ten_env_send_msg_internal@send.c:163
  Failed to send message: Failed to find destination of a 'data' message 'error' from graph.
ASR 送出了 error 資料訊息，但 websocket-example 的 graph 只路由 asr_result、metrics、tts_flush_end，沒有 error。 所以錯誤到不了前端，瀏覽器只會顯示「沒反應」。 看到「沒反應」時一定要看 log，不能相信 UI。

8. F · LLM 沒有回應

在哪看

L=$(ls -t /tmp/ten_agent/app-*.log 2>/dev/null | head -1); L=${L:-/tmp/task_run.log}
grep -E '\[llm\]|asr_result|main_control' "$L" | tail -25

LLM 節點的 name 是 llm，前綴 [llm]。 main_control 是中間的協調者：它收 asr_result，再驅動 llm。

先分辨是哪一段

看到的壞在下一步
連 asr_result 都沒有ASR回 E
有 asr_result，但完全沒有 [llm]main_control 沒把文字交給 llmF-1
有 [llm]，接著出現 HTTP 狀態碼vendor 端F-2
有 [llm] 但之後沒有下文連不到 vendorF-3

F-1　main_control 沒有收到 asr_result

檢查 graph 的 connections 有沒有這條：

python3 -c "
import json
d=json.load(open('tenapp/property.json'))
for g in d['ten']['predefined_graphs']:
    for c in g['graph'].get('connections',[]):
        print(c.get('extension'), [i.get('name') for i in c.get('data',[])])
"

main_control 那一列必須包含 asr_result。

F-2　vendor 回錯誤

grep -iE 'openai|401|403|404|429|invalid|quota|model' "$L" | tail -15
狀態碼原因
401OPENAI_API_KEY 無效
404OPENAI_MODEL 這個模型名稱不存在
429額度或速率限制
grep -E '^OPENAI_MODEL|^OPENAI_API_BASE' ~/ten-framework/ai_agents/.env

F-3　連不到 vendor

curl -s -o /dev/null -w '%{http_code}\n' -m 10 https://api.openai.com/v1/models

逾時或 000 就是網路問題。.env 的 OPENAI_PROXY_URL 可以設 proxy， 它預設是空的（placeholder 帶 |，所以空著不會讓 worker 死）。

F-4　改用本地模型

本地模型若提供 OpenAI 相容的 /v1/chat/completions，不用寫任何代碼， 改 graph 裡 llm 節點的 base_url 即可：

"property": {
  "base_url": "http://127.0.0.1:11434/v1",
  "api_key": "not-needed",
  "model": "qwen2.5:14b",
  "max_tokens": 512,
  "prompt": ""
}

api_key 不能省略也不能空 —— 多數本地伺服器不驗證它，但空字串會讓 extension 自己報錯。

9. G · TTS 沒有聲音

在哪看

L=$(ls -t /tmp/ten_agent/app-*.log 2>/dev/null | head -1); L=${L:-/tmp/task_run.log}
grep -E '\[tts\]|tts_audio_start|tts_audio_end|tts_flush|pcm_frame' "$L" | tail -25

TTS 節點的 name 是 tts，前綴 [tts]。

看到的意義
[tts] config: {...}實際設定，先確認 key 不是空的
[tts] on_start()extension 啟動了
tts_audio_start / tts_audio_end一段合成的開始與結束
沒有任何 pcm_frame 回流音訊沒送回 websocket_server

G-1　vendor 設定錯

ElevenLabs 的 voice_id 或 model_id 無效時會回錯。用 API 查你帳號實際能用的：

curl -s -H "xi-api-key: $ELEVENLABS_TTS_KEY" https://api.elevenlabs.io/v1/voices \
  | jq -r '.voices[] | "\(.voice_id)  \(.name)"'

G-2　output_format 被改過

pcm_16000 是整條 pipeline 講好的格式。改成 mp3 或其他取樣率， 下游收到的就不是預期的 PCM16 —— 音訊會壞掉而且不會有明顯的錯誤訊息。

10. 根因速查表

log 或症狀根因修法
Environment variable X is not found, neither default value is provided.env 沒有 X，或 task run 比 .env 舊填值後重啟
config: {...'api_key': ''}變數存在但值是空的填真值後重啟
STAT 欄位是 T背景執行被 SIGTTOU 停住改用 tmux
Cannot read properties of undefined (reading 'getUserMedia')非 secure contextSSH 通道 + localhost
proxy error ... ECONNREFUSED 持續不斷worker 沒起來看 B
Failed to find destination of a ... messagegraph 少一條 connection補 connections
actual_send: 0沒有音訊送到 ASR看 C、D
UI 完全沒反應，log 卻有錯error 訊息沒有被路由永遠以 log 為準
換 vendor 後行為沒變改了 addon 但沒重啟改結構要完整重啟；只改 property 值才是下個 session 生效
瀏覽器開出來是別的頁面本機 3000 被其他服務或容器佔用ss -tlnp \| grep 3000

三種改動、三種生效方式

改了什麼何時生效
property 裡的值（voice_id、model、language）下一個 session，不用重啟
addon、節點增刪、connections完整重啟 task run
.env完整重啟（只在啟動時讀一次）
