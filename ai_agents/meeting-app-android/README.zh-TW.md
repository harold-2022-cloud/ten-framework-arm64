# 會議記錄 — Android 原型：操作說明

在手機上錄下整場會議，傳給會議室的板子；板子處理完，手機上就看得到會議記錄：
整場結論、各話題的重點，以及每一句話的時間和說話人。說話人可以改成真名，
記錄也可以分享出去。English: [README.md](README.md)。

所有處理都在板子上，不連外網。任何一支裝了 App 的手機，隨時都可以送一場會議過去；
板子一次處理一場，其他的排隊，照先來後到自動處理。

## 1. 板子：只要設定一次

板子先照 [`docs/development/board_quickstart.zh-TW.md`](../../docs/development/board_quickstart.zh-TW.md)
裝好（`install_board_arm64.sh`、會議記錄用的模型、`ai_agents/.env`）。然後在 repo 根目錄，
用平常跑 `task run` 的那個終端機執行一次（sudo 會要你的密碼）：

```bash
tools/ambarella/install_board_services.sh
```

它會把原廠大模型和 API server 裝成開機自動啟動的服務，之後板子一開機就能接手機的請求，
不用再下任何指令。

- 確認狀態：`tools/ambarella/install_board_services.sh --status`。兩個服務都應該是 `active`，
  大模型的 `test_llm`、`test_llm_client` 各一個，API server 有回應。
- **每次 `git pull` 之後都再跑一次** `install_board_services.sh`：程式有改就會重新編譯並重啟服務
  （有會議在處理時不會重啟，會請你晚點再跑）。

## 2. 手機：只要設定一次

1. 安裝 APK。需要 Android 10 以上。第一次安裝會要你允許「安裝未知應用程式」；覆蓋安裝新版
   時，手機上的會議和設定都會保留。目前的版本是 **0.2.0**，App 的「設定」頁最下面看得到。
2. 手機連上跟板子同一個網路。用手機瀏覽器打開 `http://<板子IP>:8081/graphs`，看到一串 JSON
   就代表連得到。
3. 打開 App，到右上角的「設定」：
   - **板子位址**：只填 IP，例如 `192.168.1.50`，不要加 `http://`，也不要加 port。
   - **權杖**：板子有設 `MEETING_AUTH_TOKEN` 才需要填。
   - **記錄文字**：繁體或简体，之後每場會議的預設值。
   - 按「儲存」。

## 3. 開一場會

1. 首頁按 **開始錄音**。第一次會問麥克風和通知的權限，請都允許。
   錄音中可以關螢幕、切到別的 App，都會繼續錄。
2. 散會時按 **散會，結束錄音**，再按「結束」確認。
3. 填表：
   - **會議標題**：選填。
   - **與會人數**：必填。**寧多勿少**：多填一兩人幾乎沒影響，少填會把兩個人當成同一個人。
   - **記錄文字**：這場要繁體還是简体。
   - 按 **上傳到會議室的板子**。不想要這段錄音的話，按「捨棄這段錄音」。
4. 接著會進到這場會議的頁面，可以看到處理進度（見第 4 節）。處理時間大約等於會議長度；
   不用一直開著，可以先離開，**預計完成的時間到了會收到通知**，點通知就會打開這場會議。
5. 完成後，頁面上依序是：
   - **結論**：整場的結論和待辦事項。
   - **話題**：板子依停頓把會議切成幾段話題，每段有重點摘要，下面是逐句記錄：
     `[時間] 說話人N：說的話`。
6. 按 **說話人命名**，可以把「說話人1、說話人2…」改成真名；名字只存在這支手機上。
7. 按 **分享**，把整份記錄（套用你取的名字）用 LINE、Email 等傳出去。
8. 不要的會議，在它的頁面右上角按 **刪除**：手機上的錄音和記錄都會刪掉，板子上的記錄不受影響。

## 4. 畫面上的狀態

| 顯示 | 意思 |
| --- | --- |
| 還沒上傳 | 已經填好表，還沒傳成功過；可以按「上傳」 |
| 連線到板子… | 正在叫醒板子上的會議服務 |
| 上傳中… | 正在上傳錄音 |
| 上傳失敗 | 沒傳成功，下面有原因；按「重新上傳」 |
| 排隊中，前面還有 N 場 | 板子正在處理別人的會議，這場在排隊；輪到時會自動開始 |
| 排隊中，下一個就輪到 | 前面那場一做完就輪到這場 |
| 準備中 | 板子收到了，正在讀錄音 |
| 轉成文字 n / N | 一段一段轉成文字、分辨說話人 |
| 整理說話人 | 全場比對聲音，讓同一個人在每段都是同一個編號 |
| 寫摘要 n / N | 一段一段寫重點 |
| 寫結論 | 寫整場結論 |
| 完成 | 記錄已經在手機上，之後不用網路也看得到 |
| 錄音裡沒有偵測到說話 | 錄音裡沒有人聲 |
| 處理失敗：… | 板子處理到一半失敗，後面是原因；按「重新上傳」從頭再來 |

## 5. 好幾支手機一起用

板子上的大模型一次只服務一場會議，所以：

- 一場還在處理時，別支手機送來的會議會**排隊**，畫面顯示「排隊中，前面還有 N 場」，
  通知時間也會把排隊的時間算進去。
- 前一場做完，板子自動接著處理下一場，不用任何人操作。
- 同時送來好幾場時，最後一場要等前面幾場都做完，會比較久。

## 6. 出問題的時候

| 看到的 | 怎麼辦 |
| --- | --- |
| 首頁紅字「請先到「設定」填入會議室板子的位址」 | 到「設定」填板子 IP |
| 連不上板子 | 確認手機和板子在同一個網路、IP 正確、板子開著；在板子上跑 `install_board_services.sh --status` |
| 板子要求權杖 | 到「設定」填入板子的 `MEETING_AUTH_TOKEN` |
| 首頁紅字「無法開始錄音：…」 | 麥克風被別的程式占用（例如正在講電話），結束通話再試 |
| 上傳失敗 | 看頁面上的原因，按「重新上傳」；錄音一直留在手機上，不用重錄 |
| 處理失敗 | 按「重新上傳」，板子會從頭再處理一次 |
| 錄音裡沒有偵測到說話 | 手機離說話的人太遠或麥克風被遮住；下一場把手機放在桌子中間 |
| 錄完還沒送出 App 就被關掉 | 再打開 App，會自動回到「錄好了」的表單 |
| 上傳到一半 App 被關掉 | 打開那場會議，按「重新上傳」 |
| 處理很久 | 處理時間大約等於會議長度；如果在排隊，還要加上前面那幾場的時間 |
| 錄音格式不對 | 不應該再出現（0.2.0 起 App 自己寫錄音檔）；請回報，並附上「設定」頁的版本 |

## 7. 給管理者：在板子上檢查

```bash
tools/ambarella/install_board_services.sh --status          # 服務有沒有起來
python3.12 tools/ambarella/check_meeting_worker.py          # 不用手機：排隊、回收、重開，約 9 分鐘
tools/ambarella/verify_meeting_board.sh --no-meeting --phone   # 等手機送一場來，跟著檢查
tools/ambarella/rerun_meeting_worker_check.sh               # 之前卡住時：清乾淨再檢查
```

板子的 log：API server 和會議處理在 `/tmp/task_run.log`，原廠大模型在 `/tmp/log.txt`。

## 8. 原型的限制

- 板子一次處理一場會議，其他的排隊。
- 只有 Android（10 以上）；iOS 還沒開始做。
- 手機和板子之間走區網的明碼 HTTP，唯一的保護是權杖。
- 完成的會議不會自動刪錄音，要在會議頁面按「刪除」。
- 繁體只換字形、不換用語，「網絡」「反饋」會照原樣出現。

開發和建置請看 [DEVELOPMENT.zh-TW.md](DEVELOPMENT.zh-TW.md)。
